## 2. 경력 — 신한투자증권 블록체인부 인턴 (5개월)

2025.03.14~2025.08.13. 조각투자·토큰증권 등 블록체인 기반 신규 금융 서비스를 맡은 부서에서 QA, 데이터, 기획, 개발을 모두 경험했습니다.

### 2-1. 제휴사 연동 조각투자 서비스 시나리오 검증·QA

- **무엇을:** 신한 SOL증권 앱의 조각투자 서비스(제휴사 플랫폼과 연동) 통합 테스트를 설계·수행·관리.
- **테스트 시나리오 설계:** 비대면 계좌 개설 → 계좌 연동 → 청약 → 입고 등 금융 거래 단계별 시나리오를 Excel로 작성. 경계값 입력, 중복 요청 같은 엣지 케이스도 설계.
- **통합 테스트:** 앱 입력값(금액·수량)과 백오피스 처리 결과를 대사. Swagger로 API 응답을 확인하고, Oracle 기반 내부(원장) DB와 제휴사 DB를 비교해 오류 원인 추적. 기능 수정 후 회귀 테스트 수행.
- **이슈 관리:** TR(기능) 단위로 '원인 – 해결 방법 – 우선순위'를 정리해 이슈 트래킹, 오류 유형별 대응 절차 문서화.
- **핵심 에피소드 (CI 값 불일치):** 원장 DB와 제휴사 앱 DB의 CI 값 불일치 오류를 발견. 배치 처리 때마다 DB 부서에 키값 일치를 요청해야 해서 제휴사 개발 일정이 밀릴 위기였음. SQL 역량으로 DB 부서에서 관련 테이블을 받아, 불일치한 테스트 계좌의 CI 값을 직접 맞추는 방식으로 대응 → 요청·대기(약 4시간)에서 즉시 대응으로 병목 해소.
- **성과:** 배포 전 오류 **6건** 사전 발견으로 리스크 차단, 제휴사 **출시 일정 준수**.

### 2-2. '조각투자' 탭 데이터 수집 체계 설계 및 화면 개선

- **목표:** MTS 내 '조각투자' 탭 활성화. 당시에는 이용 현황을 판단할 데이터 자체가 없었음.
- **KPI 정의:**
  - 재방문율(청약 기간 외 리텐션 유지) = 탭 재진입 사용자 수 ÷ 탭 진입 사용자 수
  - 전환율 = 조각투자용 계좌 개설 수 ÷ 탭 진입 사용자 수
  - 보조 지표: 콘텐츠별 클릭률, 청약 아웃링크 이동률
- **데이터 수집:** 유입(활성 사용자 대비 탭 진입 수, 광고·배너 등 진입 경로), 행동(콘텐츠별 클릭률), 전환(탭 진입 → 청약 아웃링크) 단계로 Analytics 이벤트를 정의·삽입. 어떤 데이터를 어떻게 모을지 정해 유관 부서에 전달.
- **경쟁사 리서치:** 타사 조각투자 화면을 조사해 청약 일정을 '일정 중심'으로 노출한다는 점을 파악.
- **개선점 1 — 동선 단축:** 메인 → 정보 → 플랫폼 둘러보기 → 청약 페이지로 길었던 동선(중간 이탈 발생)을 메인 → 정보 → 청약 페이지로 단축.
- **개선점 2 — 일정 중심 재편:** 진행 중 청약은 클릭이 많고 정보성 아티클·마감 청약은 클릭이 적다는 데이터 → 마감 상품이 최상단이던 구조를 바꿔 진행·예정 청약 플랫폼을 최상단에 배치하고 **청약 일정 캘린더 뷰** 신규 기획.
- **개선점 3 — 통합 조회 신규 기획:** 유입이 광고성 배너에 의존하고 트래픽이 청약 첫날에 몰린다는 문제 → 제휴사 종목이 연결되는 통합계좌 구조를 활용해 여러 제휴사 플랫폼에 흩어진 잔고를 한 번에 보는 '통합 잔고 조회'와 정렬·필터·종목 검색·해시태그 '빠른 탐색'을 기획(메뉴바 진입으로 전환).
- **성과:** 개선안이 **'조각투자 모아보기'로 실제 배포**.

### 2-3. 토큰증권(STO) 발행·유통 플랫폼 기획

- **STEP 1 기능 명세:** 요구사항을 대분류·상세기능 단위로 나눠 기능 명세서 작성.
- **STEP 2 화면 설계:** Figma로 IA 설계, 계좌·거래·자산 화면 와이어프레임 제작. 호가·공시 등 상품 데이터와 투자금액·평가손익 등 자산 데이터를 화면별 우선순위에 맞게 배치.
- **STEP 3 데이터 항목 정의:** 협력 개발사와 주고받을 API 항목 정의·조율 (예: GET 상품 조회·상세, POST 매도/매수 주문 등록, POST 원화↔DT 교환 요청).
- **문제 해결:** 생소한 토큰증권 신규 계좌 시스템을 누구나 이해하도록 '총 자산 = 연동 계좌 잔액 + 보유 종목 평가액 + 충전 잔고' 계산식을 정의하고 항목별로 구분해 화면에 반영 → 사용자가 자산 구성을 헷갈리지 않고 확인 가능.

## 6. 강점 정리

### ① 꼼꼼한 검증과 리스크 관리 (Accuracy)

금융 거래 단계별 시나리오, 엣지 케이스, 회귀 테스트, 앱–백오피스 대사, DB 간 비교까지 '끝까지 추적하는' 검증 습관. 오류를 원인·해결·우선순위로 문서화해 팀이 재사용할 수 있게 만듦. AI 서비스에서도 800개 질문으로 응답을 점검할 만큼 신뢰를 중요하게 봄.

### ② 데이터로 문제를 찾고 개선으로 잇는 기획력

### 9-2. 상태 관리

- **서버/클라이언트 상태 분리 (Maggu):** 서버 데이터는 TanStack Query, 로그인 여부 같은 앱 상태만 Zustand. 원칙을 `docs/tech-stack.md`에 문서화. 캐시 정책 `staleTime 60초`·`retry 1`, 빈 검색어는 `enabled`로 요청 차단.
- **낙관적 업데이트:**
  - Maggu 스크랩: 응답 전에 아이콘·숫자 먼저 변경 → 실패 시 롤백(`onMutate`/`onError`) → 피드·상세·검색 3곳 캐시 무효화.
  - 청연 즐겨찾기: 같은 패턴을 Zustand + `Set`으로 직접 구현. 라이브러리 유무 양쪽 모두 경험.
- **역할별 Zustand 스토어 (청연):** 인증 / 프로필 / 서버 전송 전 임시 할 일(draft) / 즐겨찾기 4개로 분리. `draftId`로 중복 할 일 구분, 담당자 미지정 시 내 프로필 자동 채움, 스토어 간 순환 의존성은 동적 import로 회피, `hasAttemptedFetch`로 프로필 무한 재시도 방지.

### 9-3. 인증·네트워크

- **토큰 갱신 대기열 (청연):** Axios 인터셉터에서 401/403 시 토큰 갱신 후 원 요청 재시도. 동시 실패 요청이 여러 개여도 갱신은 1번만(`isRefreshing`), 나머지는 대기열(`failedQueue`)에 넣었다가 새 토큰으로 일괄 재시도. 로그인·갱신 경로는 제외해 무한 루프 방지.
- **실제 디버깅:** 서버가 만료를 401이 아닌 403으로 보내 갱신이 안 되던 문제를 찾아 수정.
- **Maggu 방어 로직:** 재발급 API가 없다는 백엔드 제약을 주석으로 기록하고, 401·502 시 로그아웃 처리(조용한 실패·깨진 화면 방지).
- **Mixed Content 해결:** HTTP 전용 백엔드를 웹은 Vercel·Vite 프록시로 같은 도메인 호출, 네이티브 앱은 직접 호출로 분기.
- **라우트 가드:** 인증 확인 전에도 토큰이 있으면 먼저 렌더해 화면 깜빡임 방지(청연).

### 9-4. 성능 최적화·UX

- **한글 IME 대응 훅 (`useImeAwareInput`):** 'ㅇ→아→안' 조합 중간 상태로 검색 API가 나가지 않도록 조합 완료(compositionend) 시점에만 검색값 확정, 입력창 표시는 그대로 부드럽게. + 디바운스 훅(`useDebouncedValue`)으로 요청 최소화.
- **지도 성능 (Maggu):** 이동·줌이 끝났을 때(`moveend`)만 뷰포트 재계산, 언마운트 시 지도·마커 정리로 메모리 누수 방지, 마커 정리 시 React 경고를 `queueMicrotask`로 해결, 마커를 사진/검색 스팟으로 분리해 조건부 표시.
- **필요할 때만 로드:** 스티커 목록은 바텀시트 열 때 조회, AI 배경 제거 모델(수십 MB)은 첫 사용 시 받아 캐시.

### 9-5. 기술적으로 눈에 띄는 기능 (Maggu)

- **SEO·GEO 대응:** SPA라 AI 크롤러(GPTBot, ClaudeBot 등)가 내용을 못 읽는 문제 → Vercel Edge Function이 장소 페이지(`/places/:id`)에 title·description·JSON-LD를 서버에서 주입. 사이트맵 자동 생성, 없는 장소는 404 + noindex, `s-maxage` 1시간 + `stale-while-revalidate` 캐시, 백엔드 장애 시 기본 SPA를 캐시 없이 반환.

- **Maggu 마커:** 게시글이 바뀔 때마다 마커 전체를 재생성(마커마다 `createRoot`) → 변경분만 반영하거나 클러스터링 여지.
- **Maggu 피드:** 무한 스크롤(`useInfiniteQuery`) 미적용.
- **청연:** `alert`, `window.location.href`, 날짜별 개수 균등 분배 임시 로직 잔존.
- **공개 저장소 정리:** Hearo_AI에 `venv` 폴더, PairMate에 `.env` 파일이 커밋되어 있음 → 공개 전 정리 권장.
